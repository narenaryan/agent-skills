# Sources and validation — distributed buffer retirement

Reviewed October 28, 2026. Cloudflare lead first discovered October 27; upstream PRs are historical backfill, not newly published articles. This original synthesis specializes RBVM verified closure for shared-memory distributed workers. It does not replace fleet coverage or policy approval. Existing Tokio cancellation safety addresses local future progress, not remote buffer reuse.

## Primary source boundaries

- [Cloudflare incident report](https://blog.cloudflare.com/kv-cache-exposure-remediation/), published October 26, 2026. Motivation: a rejected long prompt crossed a disaggregated handoff and decode read incompletely overwritten pages. Runtime pool/context checks and output validation are distinct from HTTP success. The report separates that incident from later buffer-lifetime races; this skill does likewise. Its version table recommends SGLang v0.5.22 or relevant backports, not a timeless assertion that any version eliminates every isolation failure.
- [SGLang #38935](https://github.com/sgl-project/sglang/pull/38935), created September 10, merged September 16, 2026, commit `3f8eb35eadfb29ad98d7900910f19fafcbac5ccb`. Its corrected description says the stale-KV/wrong-status behavior was already fixed by #36988 on its baseline. This is earlier retirement/waste-and-latency improvement, not a new correctness fix. Intake guards must preserve resource-owning re-entry cleanup, streaming slots and group accounting. Asymmetric rejection still timed out in the reported experiment. We did not reproduce those GPU results.
- [SGLang #41404](https://github.com/sgl-project/sglang/pull/41404), created September 27, merged September 28, 2026, commit `2a1c477648fe962627a1af091de54ca5e05859b4`. Extends deferred release beyond decode-initiated abort; partial metadata publication can expose destinations even if initialization fails. ACK tracking precedes notification; transport/backend capability matters. This supports the failure matrix, not a claim about all present backends.
- [SGLang #37077](https://github.com/sgl-project/sglang/pull/37077), created August 30, merged October 3, 2026, commit `8293f9af543a6adb8ae4269926e53c4c46d1f585`. Common drain acknowledgment uses lifecycle generations and participant accounting; Mori support and backend-specific tests are explicit. The model checks these invariants without importing this implementation.
- [SGLang #43719](https://github.com/sgl-project/sglang/pull/43719), created October 11, merged October 12, 2026, commit `4195980f5a3d1efd9d1ab5d8a6c368b94122c950`. A failed Mooncake send may leave writes running. Suppressing a false drained ACK falls back to the release timeout; the PR explicitly leaves richer transport completion reporting outside scope. Consequently a merged patch or received error is not a universal quiescence proof. Our model deliberately withholds reuse without all drain evidence; it does not describe SGLang's timeout fallback as unlimited retention.

PR descriptions and merge metadata were read directly through GitHub on the review date. Release inclusion is attributed to the incident report, not independently established by tag ancestry. No broad SGLang upgrade recipe is supplied.

## Original isolated experiment

Run `python3 skills/security/distributed-buffer-retirement/reproduce.py` from repository root. Only installed Python standard-library modules are used; no network, subprocess, GPU, external package, or host configuration changes.

On Python 3.12.14, normal and optimized execution passed all nine unittest methods. They check pending-vs-finished rejection, resource-owning and empty-marker re-entry, incomplete initialization, delayed writes following three local failure labels, all six valid interleavings of two writes and their acknowledgments, stale/duplicate/unknown/unarmed acknowledgments, failed-send uncertainty, arbitrary timeout reuse, and lost acknowledgment. The failure labels exercise the same model transition, not three real backend integrations.

The baseline allows premature reuse and visibly overwrites synthetic tenant B with A's delayed marker. The guarded policy withholds reuse until every modeled writer has drained and supplied a current-generation acknowledgment. It deliberately fails closed on lost evidence despite actual completion; this demonstrates the safety/liveness tradeoff, not a production capacity policy. The initialization check is separate from retirement: waiting for writers does not prove every expected range was initialized.

Limits: finite event model, two writers, no true concurrency, RDMA, DMA ordering, GPU allocation, authentication, transport fencing, offload reader implementation, integration of partial-publication cleanup, symmetric/asymmetric peer error propagation, resource-exhaustion behavior, runtime version coverage, exhaustive state-space exploration, or empirical performance proof. The model assumes truthful drained ACKs and a complete participant set; the recipe requires independent evidence for those assumptions. Do not run cross-tenant probes or change production containment without separate authorization.
