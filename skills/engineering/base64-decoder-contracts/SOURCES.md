# Base64 decoder contracts: provenance and limits

Reviewed 2026-10-29. Original synthesis, not a claim that a particular accelerated library is incorrect or that a published benchmark is unfair.

## Sources

- [Daniel Lemire: Decoding base64 in Python at 10 gigabytes per second](https://lemire.me/blog/2026/10/17/decoding-base64-in-python-at-10-gigabytes-per-second/), published 2026-10-17; historical backlog lead reviewed October 29, not newly published today. It reports decoded-byte throughput for particular sizes, CPU, Python and library versions, including wrapped input. We did not reproduce its speed claims.
- [Author's benchmark](https://github.com/lemire/Code-used-on-Daniel-Lemire-s-blog/blob/master/2026/10/pybase64/bench.py), source blob `07784d8c19fc15a2c9e8dbd0e37a02902f5d0dde`, read but not executed. It checks output equality, separates validation modes, deliberately skips strict decoding of MIME-style input, prepares input outside timing, and reports decoded bytes divided by the best repeated duration. These are valid scope choices, not evidence of a defect. Valid-input speed measurements alone do not settle replacement compatibility on malformed inputs.
- [fastpybase64 README at reviewed revision](https://github.com/simdutf/fastpybase64/blob/4d27daca7333f05bb4b60cf297ada564cb440d76/README.md), revision dated 2026-10-17. The wrapper describes compatibility checks and fallback because underlying forgiving-base64 rules differ from Python's. Its upstream compatibility and performance claims were not independently executed here. The lesson is to measure the wrapper contract, not substitute a differently configured kernel. We neither installed nor recommended a particular package/version.
- [Python 3.12 Base64 documentation](https://docs.python.org/3.12/library/base64.html), page updated 2026-10-26. Documents default removal of non-alphabet characters, `validate=True`, alternate alphabets and padding errors. Runtime fixtures used CPython 3.12.14. Current unversioned documentation already describes 3.15 additions (`canonical`, `ignorechars`, `padded`); these are not assumed available in 3.12. Recheck version-specific behavior rather than extrapolating the fixtures to every interpreter.
- [RFC 4648](https://datatracker.ietf.org/doc/html/rfc4648), October 2006, §§3.1–3.5 and 5. Separates line feeds, padding, non-alphabet policy, alphabets and canonical pad bits; referring specifications can define exceptions. Strict-alphabet acceptance is not identical to canonical spelling. Exact re-encoding implements the deliberately narrower local profile, not all protocol variants.
- [Python 3.12 timeit documentation](https://docs.python.org/3.12/library/timeit.html), page updated 2026-10-26. Setup is outside timing; GC is disabled by default; minimum repeats provide a lower-bound microbenchmark observation. End-to-end latency, cache behavior and production workload distributions require separate measurement.

## Validation

`reproduce.py` contains original, isolated standard-library cases. It contrasts permissive decoding with the local canonical profile, proves strict validation accepts nonzero pad bits on the tested interpreter, tests both one- and two-byte final groups, rejects malformed padding and alternate alphabets, limits normalization to CR/LF, checks API types, exposes equal-length wrong outputs, and distinguishes input/output throughput denominators. An operation-count case shows normalization belongs to every complete call; it is not a timing measurement.

Twelve tests pass normally and under `python -O` on CPython 3.12.14. The profile is bytes-only, standard alphabet, canonical padding, no whitespace; the second profile permits only CR/LF before the same canonical check. Empty bytes are valid. No resource-limit, streaming, MIME parsing, SIMD, third-party compatibility, timing, production performance or cross-version assurance is claimed. The fixture is not a production decoder recommendation or permission to tighten application inputs.

Independent source/content review confirmed the pinned wrapper README and benchmark source. Nineteen additional edge cases passed; the original suite caught three deliberate faults: removing canonical re-encoding, corrupting output without changing its length, and accepting all whitespace. Changing only `validate=True` to `False` survived because exact re-encoding still rejects noncanonical input under this narrow profile; an equivalent mutant is not evidence of a missing behavioral test.

## Relationship to existing skills

The scaling regression skill measures growth after choosing a workload. Patch reproducer validity compares a repair with surrounding behavior. This skill supplies Base64-specific acceptance and canonicalization probes that determine whether decoder timings compare the same work. A faster candidate that fails the chosen contract is not an optimization of that contract. Any new contract still requires its own approval and migration plan.
